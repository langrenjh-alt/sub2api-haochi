# Codex 状态池：双向移组与采集通道

## 行为与默认值

本次保留自研状态池，不合并官方版本，不增加多模型池、WS 注入或逐请求无票拦截。
升级后 `transfer_enabled=false`、`harvest_transport="account"`，现有配置继续生效。

后台状态池页面可以指定一对 A（可用）与 B（待恢复）分组。状态池、注入和移组开关同时开启时：

- A/B 中的账号按当前绑定票据资格归组：长度策略、采集模型、到期时间、撤销状态共同决定；未记录模型的票据不视为模型匹配，需重新采集。B 中原有账号也能恢复到 A。
- 仅交换 A/B 绑定，保留其他组及其优先级，不改人工禁用、限流等账号状态。
- 续采失败不覆盖有效旧票；新票据持久化并绑定后才允许晋级。临近过期只续采，不提前移走。
- 启动、配置保存及票据事件触发核对；额外每 5 秒补偿扫描到期票据和复活账号。数据库读错不作为“无票”处理。
- 移组提交后主动刷新调度快照，事务内 outbox 提供重试。已开始的请求不中断，存在异步更新窗口。
- 人工移出 A/B 后不拉回；关闭规则不回滚已完成移组。同一对分组的旧降智自动移组与本规则互斥。

每轮次数上限保留。A/B 内达到上限的账号默认等待 300 秒后重试，冷却可配置。
轮次冷却和上游退避时间持久化；重启、清理历史不会绕过。
手动采集只重置轮次冷却，不取消上游退避，同账号重复点击不增加并发。

## 管理接口扩展

沿用 `/api/v1/admin/codex-turn-state` 和 `/config`。新增配置字段：

```json
{
  "transfer_enabled": false,
  "transfer_ready_group_id": 0,
  "transfer_recovery_group_id": 0,
  "cycle_cooldown_seconds": 300,
  "harvest_transport": "account"
}
```

这是完整配置中的新增字段，不是独立的 PUT 请求体；更新时须保留其他原有字段。
长度仍为 `target_state_length=0/292/332`，0 同时接受已知的个人与 Team 正常形态。
概览增加票据资格、当前分组、移组错误、重试时间及最近 50 条移组记录，不返回原始票据。

## 独立采集模式

`harvest_transport="independent"` 要求有效的 `proxy_id`。它只改变主动采集：
使用专用 HTTP/1.1 profile、关闭连接复用和重定向，绕过业务插件，保留账号流量控制、
请求身份构造及重试策略。失败不自动改用业务代理；业务流量和正常代理设置不变。
每次新建连接不代表代理商必然分配不同 IP，效果需要实际观测。
切回 `account` 即恢复原有账号测试/插件/TLS 通道，不清除现有票据。

## WishTeam5X 复活

WishTeam 当前采用存档、软删除、重新导入，因此本地账号 ID 会改变。
仅在邮箱、上游工作区及已有用户/组织身份一致时，在同一个复活事务内：

- 为新 ID 复制当前合格、未撤销、未过期票据，保留原 `issued_at`、`expires_at` 和票据内容。
- 继承次数与轮次/上游冷却，不重新计时；保存新旧 ID 的关联记录，旧票据历史留存。
- 复活事务失败时票据继承一起回滚；重复应用复活结果不重复复制。
- 不继承已过期、被撤销、模型/长度不合格或身份变化的票据。
- 随后的状态池核对加载继承票据，再按 A/B 规则归组；不保证上游永远接受旧票据。
